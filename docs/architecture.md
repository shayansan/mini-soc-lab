
## Mini SOC Architecture

## Machines
	## Attacker

	OS: Kali Linux
	Purpose: Generate controlled attack and suspicious activity against the victim machine.
	Examples:
	Failed login attempts
	Port scanning
	Brute-force simulations
	Network reconnaissance	
	## Victim

	OS: Windows 11
	Purpose: Act as the monitored endpoint and generate security telemetry during normal and suspicious activity.
	The victim will send its security events to the SIEM server.

	## SIEM Server

	OS: Ubuntu Server
	Purpose: Run Wazuh and collect, analyze, and display security events generated by the victim machine.
	The SIEM server will be used for:
	Log collection
	Detection
	Alert generation
	Investigation
## Tools

	## Virtual Box
	
	Used to create and run the virtual machines used in the lab.
	It allows the attacker, victim, and SIEM server to run as separate systems on the same physical computer.
	It will also allow us to create an isolated virtual network for the security lab.
	
	## Wazuh

	Used as the SIEM/XDR platform.
	It receives security telemetry from monitored endpoints.
	It analyzes events using detection rules and generates alerts when suspicious activity is detected.
	It provides a dashboard where alerts and security events can be investigated.
	
	## Wazuh Agent

	Installed on the victim machine.
	It collects security information from the victim and sends it to the Wazuh server.
	This allows the SIEM to monitor activity happening on the endpoint.
	
	## Sysmon

	Installed on the Windows victim.
	It provides detailed Windows security telemetry.
	It can record information such as:
	Process creation
	Network connections
	File creation
	Registry activity
	Process relationships
	
	Sysmon gives us more detailed endpoint information than relying only on basic Windows logs.

	## Windows Event Logs
	
	Native Windows logging system.
	Used to record important operating system and security events.
	Useful events include:
	Successful logins
	Failed logins
	Account creation
	Process execution
	Security policy changes

	## Linux Logs
	
	Used on the Linux systems to understand authentication, system, and service activity.
	They may later be useful for investigating activity on the attacker or SIEM server.
	PowerShell
	Native Windows command-line and scripting environment.
	It is useful for both legitimate administration and security testing.
	PowerShell activity is important to monitor because attackers commonly abuse scripting environments during attacks.

	## Git

	Used to track changes to the project.
	It will keep the project history organized and allow the lab documentation to be stored in a Git repository.
